# 演示步骤

前端默认是 Mock 模式，适合离线讲解交互。比赛联调时可切到 Live 模式，让请求经过 FastAPI、策略网关和 Mock 工具。不要把 Live 里的内存工具说成真实邮件、日程或共享盘。

## 准备

### Mock

```powershell
cd frontend
npm install
npm run dev
```

### Live

先启动根目录 API，再把 `frontend/.env.local` 设置为 `VITE_DATA_MODE=live`：

```powershell
python -m pip install -e ".[api]"
uvicorn backend.api.server:app --reload --port 8000
```

## Live：真实输入参数链路

在任务控制台填写未来活动时间、地点、`example.org` 域名下的接收地址、接收人数和通知内容，先点击“预览本次权限与风险”，观察操作的预估决策。保留“同时更新共享活动文件”时，提交后到执行轨迹查看三角色规划证据、任务护照、日历工具请求和文件更新审批；批准文件更新后，12 人通知可自动完成。取消该选项再运行一次，可看到预览、任务护照和执行轨迹都不含文件更新，且无需文件审批；若人数改为 40，通知仍需审批。全部为内存模拟工具，并非真实发送。Live 模式默认使用本地离线规划器，不能作为已接入 AgentArts 的证明。

可上传仓库内的 [`activity-reference-injection.txt`](../examples/activity-reference-injection.txt) 或 [`activity-roster-synthetic.csv`](../examples/activity-roster-synthetic.csv)（均为虚构样例）。前者展示外部资料中的越权指令会被标记，但不会改写结构化收件地址；后者展示姓名、手机号列被排除，行值不进入任务记录。轨迹页能查看 `SOURCE_INSPECTED` 摘要。检测规则只是启发式，不能将“未命中”解释成安全；目前资料仅供来源检查，不自动生成活动计划。演示不可上传真实名单或私密文档。

上传 CSV 后点击“核对资料与通知人数”：样例有 2 行，默认拟通知 12 人，页面会提示核对差异、敏感列，并基于 `availability` 给出匿名的上午/下午排班草案（只显示行号，不显示姓名电话）。把人数改成 2 后，旧建议立即失效；重新核对后会显示“行数一致仍不代表已获授权”。排班必须由人对照原始名单和意愿核实，不会自动写入文件、修改人数或发送通知。答辩时可把它与权限预览、审批和轨迹串成一次演示；这还不是从策划书自动提取活动信息的完整业务 Agent。

以下四个预置场景仅在 Mock 回放中选择；后端仍保留对应接口供自动化回归。

## 1. 正常放行

任务控制台选择“正常放行”并启动。查看来源、工具请求、`ALLOW`、策略证据和执行结果。

## 2. 人工审批

选择“人工确认”并启动。40 人通知触发 `CONFIRM`。在人工审批页检查范围、规则和完整参数；批准后工具执行一次，拒绝则不执行。审批 60 秒过期，过期后批准也不会执行。重复决策返回冲突。

## 3. 越权阻断

选择“越权阻断”。外部不可信指令请求把敏感字段发给外部邮箱。查看 `BLOCK` 和命中证据；确认没有对应的工具执行事件。前置的低风险日程可以成功，阻断只针对危险请求。

## 4. 熔断恢复

选择恢复场景并批准共享文件更新。后端首次真实执行失败，随后继续失败两次；达到三次阈值后熔断、取消待发通知，并把共享文件恢复到操作前快照。比较前后内容并导出完整 Trace。

## 5. 评测看板

查看指标分母与公式，切换类别、搜索、结果、翻页并导出。60 条均为合成演示样例，不是实测；故意保留失败样例用于展示边界，不声称全部通过。

## 答辩说明

可以展示确定性策略、人工确认、审计证据、失败熔断和快照恢复。当前后端是演示编排层，没有真实登录、持久化数据库和多用户隔离；每个 API 进程重启后状态清空。
