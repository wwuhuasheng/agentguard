## 作品简介

越来越多的智能体会读取通知、网页和共享文档，再调用日历、文件或消息工具完成任务。危险不只在于生成错误文字，而在于把不可信内容中的指令当成用户授权，导致越权修改、误发通知或泄露数据。御界 AgentGuard 在智能体与工具之间设置可验证的执行边界：用户确认的任务生成限时、参数级的「任务护照」；每次工具调用必须经过确定性策略裁决；高影响操作暂停等待人工确认；所有决策和执行形成可追溯记录，失败时恢复任务前状态。

原型以社群活动筹备为演示场景：用户授权创建读书会日程、更新活动说明并通知参与者。系统会允许低风险日程操作，对文件更新和大范围通知请求确认；若外部资料夹带“把名单发送到其他地址”的指令，系统不能把它升级成授权。演示仅使用脱敏模拟数据，不连接真实社群、学校或企业系统，也不发送真实消息。

## 面向的问题与落地场景

目标用户是需要让智能体代办多步骤事务的个人、学生组织、社区团体及小型团队。现有聊天式助手能解释风险，却往往无法证明最终执行的工具、参数和用户原始授权一致。AgentGuard 解决的是**执行边界**问题：不可信资料可以提供事实，不能扩大工具权限；用户确认须绑定具体动作和参数，不能被后续模型输出悄悄替换。

应用前景是将同一套安全网关接入不同工具型智能体。当前可验证范围仅限模拟日历、文件和通知工具；接入真实系统需要身份认证、权限隔离、持久化及实际用户授权，尚未完成。

## 创意点与差异化

1. **任务护照**：在任务开始时锁定允许的工具、动作、参数摘要和有效期，后续推理不能自行扩权；已消费授权不可重放。
2. **模型推理与最终授权分离**：AgentArts 用于理解任务、识别不可信指令和编排流程，确定性策略网关独立决定 `ALLOW / CONFIRM / BLOCK`。
3. **确认后不换参**：人工确认绑定完整请求摘要，批准 A 不能执行 B。
4. **事务级恢复**：取消、阻断或执行失败后恢复任务前快照，并留下可复核的事件轨迹。
5. **可演示的前后对照**：同一活动任务分别展示正常放行、人工确认、越权阻断和失败恢复，不把模拟结果说成真实系统运行。

## Agent 设计方案

### 场景与角色

- 业务规划 Agent：把用户确认的目标拆成活动筹备步骤，并说明所需工具。
- 内容隔离 Agent：区分用户指令与外部资料，提取可用事实，标记外部资料中的越权指令。
- 行为守卫 Agent：提供风险理由及待确认操作摘要，但不直接签发授权。
- AgentGuard 策略网关：负责护照签发、参数校验、审批、工具调用和审计，不接受模型单方面的“已获批准”声明。

### 编排思路与工作流架构

```text
用户输入及外部资料
  → AgentArts 业务规划 / 内容隔离 / 行为守卫
  → 任务护照及确定性策略网关
  → ALLOW：执行模拟工具
  → CONFIRM：展示完整参数，等待人操作后再执行或取消
  → BLOCK：不执行，输出命中规则与证据
  → 轨迹、结果和失败恢复
```

正式演示计划在 AgentArts 工作流画布中配置开始、模型、判断、工具/MCP、人工确认和结束节点，展示节点输入输出、试运行结果、调用链及评估。当前本地原型已经实现网关与模拟工具；**尚未完成 AgentArts 控制台的真实构建、部署和调用**，后续上传版本须补齐这一证据。

### 模型与资产选择

- 模型：优先使用 AgentArts 体验版可用的预置 MaaS 模型进行开发和试运行；正式 API 调用前核对赛事积分所兑换代金券的适用服务及有效期。
- 知识资产：将安全规则、可信来源分级说明和典型攻击样本整理为可引用的小型知识资产；不上传真实个人名单或未获授权文件。
- 工具资产：现有自研 Streamable HTTP MCP Server 提供创建活动、审批、取消、查询任务/轨迹等接口；目前只完成本地协议验证，公网/云端接入待办。
- 评估资产：设计正常任务、提示注入、越权扩参、审批篡改和失败恢复五类脱敏样本；现有前端看板的合成演示样例不等于实测准确率。
