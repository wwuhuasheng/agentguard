# 成员 C 当前任务交接（初赛）

依据团队分工，成员 C 负责评测数据、实验、回归测试与交付材料。当前不用等待 A 的 AgentArts 云端接入，以下工作可以立即并行推进。

## 本周先交付

1. **样本规范与首批 20 条**：在 `evaluation/datasets/` 提交 JSONL，先覆盖正常业务、边界授权、外部指令、越权、参数异常和故障恢复。每条至少写 `id`、`category`、用户原始目标、资料来源、预期工具及参数、预期 `ALLOW/CONFIRM/BLOCK`、预期最终业务状态、人工标注理由。编号唯一，所有姓名、电话和地址都用虚构值。参考 [`虚构活动联调样本说明`](../examples/虚构活动联调样本说明.md)，但不要把同一个样本换措辞充数。
2. **评测口径一页纸**：固定风险阻断率、正常任务成功率、误报率、确认覆盖率和恢复成功率的分子、分母与失败判定；明确“系统无法运行”计入失败，不从分母排除。把“仅提示词”“提示词+关键词”“完整方案”三组使用同一批样本的运行方法写清楚，先不填未经运行的结果。
3. **回归测试与缺陷台账**：从现有接口开始，至少覆盖资料不改授权、审批过期、参数替换、越权工具调用、连续失败恢复。记录真实发现的缺陷、复现步骤、修复提交及复测结果；不能为凑数量虚构缺陷。
4. **需求访谈准备**：整理 5—8 个非引导性问题，联系真实活动组织者或小型团队。记录他们的实际流程、最担心开放的权限和现有耗时；征得同意后只保留匿名摘要。虚构样本不能替代访谈。

## 等待 A/B 联调后再做

- A 提供稳定的批量运行入口后，把样本扩充到策划案要求的 60 条，执行三组对照实验并复核指标。
- AgentArts 真实工作流上线后，在平台运行相同的代表性案例，保存画布、Trace 和评测截图；不要把本地离线适配器结果写成云端结果。
- B 接入真实指标后，核对评测看板、报告、PPT 与视频中的数字和分母完全一致。

## 给 A 的首次 PR 验收点

首批 PR 先提交样本规范、20 条有人工标签的 JSONL、评测口径和至少 3 条可复现的接口回归测试。暂不要求漂亮图表，也不要求 C 代替 A 开发策略引擎。数据字段或 API 不确定时，先提议契约变更，避免直接改动 `backend/` 公共对象。
